# ARCHIVE INDEX

## Purpose

ARCHIVE INDEX defines how SAB’A preserves documents, records, and information that are no longer part of the active Codex.

The archive protects project history while keeping active documentation clear, current, and controlled.

## Archive Principles

Archived material should be:

- Preserved without unnecessary modification
- Clearly identified
- Traceable to its original context
- Separated from active documentation
- Retained when it has historical, operational, or reference value

## What May Be Archived

Material may be archived when it is:

- Replaced by a newer approved version
- No longer applicable
- Superseded by a new decision
- Completed and no longer actively used
- Retained for historical reference
- No longer required in the active workflow

## Archive Record

Where practical, archived items should retain:

- Original filename
- Original location
- Archive date
- Reason for archiving
- Replacement document, if applicable
- Relevant version information

## Archive Control

Archived documents should not be treated as current requirements unless explicitly restored or referenced for historical context.

The latest approved active document remains the primary reference for current decisions.

Archived material should not be deleted solely because it is no longer active when its historical or traceability value remains important.

## Restoration

An archived document may be restored when there is a valid business or documentation need.

Restoration should be controlled and should not create conflicting active versions.

If restored for active use, the document should be reviewed and updated according to the current SAB’A Codex standards.

## Relationship with the Codex

The Archive is a historical layer of the SAB’A Codex.

It preserves the evolution of the project without allowing outdated information to interfere with current standards, decisions, or operations.

## Core Principle

> SAB’A should preserve its history without allowing the past to control the present.
