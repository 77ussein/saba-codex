# Returns and Exchanges

## Purpose

The SAB’A returns and exchanges system defines how customers can resolve eligible purchase issues after receiving an order.

A return is not treated as a failure of the relationship.

It is another customer experience that must be handled with the same:

- Clarity
- Fairness
- Respect
- Speed
- Precision
- Service

The governing principle is:

**A difficult post-purchase moment should never become a difficult relationship.**

---

# Returns Philosophy

SAB’A should make eligible returns and exchanges understandable without making them unnecessarily complicated.

The customer should always know:

**What is eligible → What to do → What happens next → When the issue will be resolved**

The process must protect both:

**Customer Trust**

and

**Business Integrity**

---

# Return Journey

The standard return journey is:

**Request → Eligibility Check → Approval → Return → Inspection → Resolution → Refund / Exchange → Completion**

The exact process may vary depending on:

- Product
- Market
- Reason for return
- Condition
- Local regulations

---

# Exchange Journey

Where exchanges are supported:

**Request → Eligibility Check → Product Availability → Return → Inspection → Replacement → Delivery**

If the requested replacement is unavailable, the customer should be offered an appropriate alternative resolution.

---

# Eligibility

Every product must have clearly defined return and exchange eligibility.

Eligibility may depend on:

- Product type
- Condition
- Purchase date
- Packaging
- Product usage
- Market
- Legal requirements

The customer should be able to understand the rules before purchasing.

---

# Return Window

Each eligible product or market should have a clearly defined return period.

The system should communicate:

- Start date
- End date
- Conditions
- Exceptions

Dates should be calculated consistently by the ecommerce system.

---

# Non-Returnable Products

Certain products may be excluded from returns or exchanges where justified by:

- Product nature
- Hygiene
- Personalisation
- Customisation
- Regulatory requirements
- Applicable law

Any exclusions must be clearly communicated before purchase.

---

# Product Condition

Returned products may need to meet defined condition requirements.

Where applicable, the product should be:

- Unused
- Undamaged
- In original condition
- Accompanied by required packaging
- Accompanied by relevant components

The exact requirements should be communicated clearly.

---

# Damaged Products

If a product arrives damaged, the customer should not be treated as though they initiated a normal return.

The system should provide a dedicated path for:

- Damage reports
- Evidence where appropriate
- Investigation
- Replacement
- Refund
- Customer care

The objective is to resolve the problem quickly.

---

# Incorrect Products

If the customer receives the wrong:

- Product
- Variant
- Quantity
- Order

SAB’A should provide a clear correction process.

The customer should not be responsible for unnecessary costs caused by an internal fulfilment error.

---

# Defective Products

If a product has a genuine defect, the customer should have a dedicated resolution path.

Depending on the situation, this may include:

- Replacement
- Repair where applicable
- Refund
- Other approved resolution

---

# Return Request

Customers should be able to initiate a return through an appropriate channel.

Potential channels include:

- Customer account
- Website
- Customer care email
- WhatsApp
- Customer support

The preferred digital route should be simple and easy to understand.

---

# Customer Account Returns

Customers with an account should be able to locate an order and initiate an eligible return without repeatedly entering information already stored in the system.

The account may display:

- Eligible orders
- Eligible products
- Return window
- Return status
- Instructions
- Resolution status

---

# Guest Returns

Customers who purchased as guests should still have access to an appropriate return process.

The system may identify the order through:

- Order number
- Email
- Other approved verification information

Guest customers should not be forced to create an account merely to request a legitimate return.

---

# Return Reasons

The system may collect a return reason to improve service and operations.

Possible reasons may include:

- Wrong product
- Damaged product
- Defective product
- Incorrect size or variant
- Change of mind
- Other approved reason

The customer should not be required to provide excessive information.

---

# Return Approval

Where approval is required, the customer should receive a clear result.

Possible states include:

- Return approved
- Return pending review
- Return rejected
- Additional information required

If rejected, the customer should receive a clear explanation.

---

# Return Instructions

Approved returns should include simple instructions covering:

- What to return
- How to package it
- Where to send it
- Return method
- Tracking
- Expected next step

Instructions should avoid unnecessary complexity.

---

# Return Shipping

Return shipping responsibility must be clearly defined.

Depending on the reason and applicable policy:

- SAB’A may cover the cost
- The customer may cover the cost
- The cost may be deducted from the refund where legally and commercially appropriate

The customer should know the applicable rule before completing the return.

---

# Return Tracking

Where a return shipment is required, tracking should be available where practical.

The customer should be able to understand:

- Return shipped
- Return received
- Return under review
- Resolution approved
- Refund or exchange completed

---

# Return Receipt

When SAB’A receives a return, the customer should receive confirmation.

This confirms that:

**The returned product has arrived and the resolution process has begun.**

---

# Return Inspection

Returned products may be inspected according to the applicable policy.

Inspection may verify:

- Product identity
- Condition
- Completeness
- Eligibility
- Damage
- Usage where relevant

The inspection process should be consistent and fair.

---

# Refunds

If a refund is approved, the system should communicate:

- Refund amount
- Refund status
- Original payment method where applicable
- Expected processing timeframe

Refunds should be linked to the original transaction whenever possible.

---

# Partial Refunds

Where appropriate, partial refunds may be supported.

The customer should clearly understand:

- Refunded amount
- Reason
- Remaining amount
- Resolution status

---

# Refund Timing

SAB’A should communicate realistic refund expectations.

The customer should understand the difference between:

**SAB’A approving the refund**

and

**The payment provider or bank completing the refund**

SAB’A should not promise a financial institution's processing time as though it were fully controlled by the house.

---

# Exchanges

Where exchanges are supported, the system should make the process clear.

The customer should understand:

- What can be exchanged
- What variants are available
- Whether price differences apply
- Whether shipping is involved
- What happens if the replacement is unavailable

---

# Price Differences

If an exchanged product has a different price, the system must define how the difference is handled.

Possible outcomes may include:

- Additional payment
- Partial refund
- Equivalent replacement
- Other approved resolution

The customer must know the financial impact before confirming the exchange.

---

# Out-of-Stock Exchanges

If the requested replacement is unavailable, the customer should receive an alternative.

Possible options may include:

- Different variant
- Different product
- Refund
- Other approved solution

The customer should never be promised a replacement that cannot be fulfilled.

---

# Gift Returns

Where gifting is supported, the return experience should account for situations where:

- Recipient initiates the return
- Purchaser receives the refund
- Recipient receives an exchange
- Gift information must remain private

The exact behaviour should follow the applicable commercial and legal rules.

---

# Customer Care

Customer care is a central part of the returns experience.

Support may be provided through:

- Customer care email
- WhatsApp
- SAB’A AI
- Human support

Customer care should have access to the relevant order context so the customer does not need to repeatedly explain the same situation.

---

# Email Support

A dedicated customer-care email may handle:

- Return requests
- Exchange requests
- Complaints
- Damaged orders
- Refund questions
- Delivery issues

This channel should be treated separately from marketing and promotional email.

---

# WhatsApp Support

WhatsApp may support faster customer communication for:

- Return questions
- Exchange guidance
- Delivery issues
- Refund status
- General assistance

Customers should never be asked to send unnecessary sensitive financial information through WhatsApp.

---

# SAB’A AI

SAB’A AI may assist customers with:

- Return eligibility information
- Policy explanations
- Return instructions
- Order lookup where integrated
- Return status
- Exchange guidance

AI must rely on verified ecommerce information.

It must never:

- Invent eligibility
- Promise a refund without approval
- Override policy without authorised capability
- Guarantee an exchange that is unavailable
- Invent a return status

Complex or sensitive cases should be escalated to human customer care.

---

# Customer Communication

Returns and exchanges should generate appropriate notifications.

These may include:

**Request Received → Approval → Return Received → Inspection → Resolution → Refund / Exchange Completed**

Communication should be timely and useful.

Customers should not need to repeatedly ask for updates.

---

# Customer Account Status

The customer account should display relevant return information.

This may include:

- Return request
- Return reason
- Return status
- Tracking
- Refund status
- Exchange status
- Resolution

---

# Privacy

Return information may contain personal and order-related information.

It must be handled securely.

Customer data should only be accessible to authorised systems and personnel.

---

# Fraud and Abuse Prevention

The returns system should protect against legitimate fraud and repeated abuse.

Controls may include:

- Return history
- Order verification
- Eligibility checks
- Product verification
- Fraud monitoring

Controls should not create unnecessary friction for legitimate customers.

---

# Exceptions

Customer-care teams may need to handle exceptional situations.

Exceptions should be:

- Documented
- Authorised
- Consistent
- Traceable

Exceptions should not become hidden policies.

If a recurring exception appears frequently, the underlying policy should be reviewed.

---

# Complaints

A complaint related to a return or exchange should have a clear escalation path.

The objective is:

**Understand → Resolve → Learn → Improve**

Complaints should be treated as operational feedback, not merely individual incidents.

---

# Returns Data

The business should monitor:

- Return rate
- Exchange rate
- Return reasons
- Damaged product rate
- Defect rate
- Refund time
- Exchange completion time
- Customer satisfaction
- Return shipping cost

This data should be used to improve:

- Products
- Packaging
- Fulfilment
- Product descriptions
- Sizing information
- Customer communication

---

# Returns and Product Catalogue

Return eligibility should be connected to product data.

The ecommerce system should know when a product has:

- Special return rules
- Non-returnable status
- Variant-specific conditions
- Market-specific restrictions

Customer-facing information must reflect the current catalogue rules.

---

# Returns and Payments

Returns must integrate with the payment system.

The system should correctly support:

- Full refund
- Partial refund
- Original payment method
- Payment status
- Refund status

Detailed payment rules are defined in:

**5_Payments.md**

---

# Returns and Shipping

Returns must connect to the shipping system.

The customer should be able to understand:

- Return shipping method
- Return cost
- Tracking
- Receipt
- Resolution

The shipping system should maintain visibility throughout the return journey.

---

# Returns and Loyalty

If a returned purchase previously generated loyalty points or rewards, the loyalty system must correctly account for the return.

This may include:

- Reversing points
- Adjusting membership progress
- Cancelling rewards where applicable

The customer should receive clear information when a return affects their loyalty status.

---

# Returns and Promotions

If a returned product was purchased using:

- Coupon
- Promotion
- Loyalty benefit
- Bundle pricing

the refund calculation must follow the original transaction rules.

The customer should be able to understand how the final refund was calculated.

---

# International Returns

International returns may require additional handling for:

- Customs
- Duties
- Return shipping
- Taxes
- Local regulations
- Carrier restrictions

International return requirements must be communicated clearly before purchase where possible.

---

# Return Quality Audit

Before launching or changing the returns system, verify:

1. **Can customers understand the return policy?**
2. **Can eligible customers initiate a return easily?**
3. **Can guest customers return orders?**
4. **Are eligibility rules accurate?**
5. **Are non-returnable products clearly identified?**
6. **Can customers track their return?**
7. **Are refunds processed correctly?**
8. **Are exchanges handled correctly?**
9. **Are price differences handled correctly?**
10. **Can customer care access the relevant order information?**
11. **Can AI provide verified policy information?**
12. **Are email and WhatsApp updates accurate?**
13. **Are loyalty adjustments correct?**
14. **Are promotional purchases handled correctly?**
15. **Does the entire process remain worthy of SAB’A?**

---

# What Returns Must Never Become

Returns must never feel like:

- A punishment
- A maze
- A hidden policy
- An argument with the brand
- An unnecessarily long process
- A disconnected customer-service experience

The customer should never feel that buying from SAB’A was a mistake simply because they needed to return something.

---

# Core Standard

The ideal SAB’A returns experience is:

**Clear enough to understand.  
Fair enough to trust.  
Simple enough to complete.  
Personal enough to feel cared for.**

---

# Core Statement

The relationship with the customer does not end when a product is returned.

A well-handled return can strengthen trust.

Therefore:

**Make the policy clear.**

**Make the process simple.**

**Resolve problems fairly.**

**Communicate consistently.**

**Learn from every return.**

The goal is not to eliminate every return.

The goal is to ensure that every legitimate return is handled with the same standard of care as the original purchase.

**A customer who returns a product should still feel welcome in the house.**
