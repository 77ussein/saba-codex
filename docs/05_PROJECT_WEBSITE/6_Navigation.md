# Navigation

## Purpose

Navigation is the invisible structure that allows the visitor to move through the world of SAB’A.

It must provide direction without becoming dominant.

The visitor should always know:

- Where they are
- Where they can go
- How they arrived
- How to return
- What the next meaningful action is

Navigation should feel effortless.

The visitor should not think about the navigation system.

They should simply feel that the website understands where they want to go.

---

# Navigation Philosophy

SAB’A navigation is not a technical menu.

It is the system through which the house reveals itself.

The principle is:

**Guide without forcing.**

Navigation must balance two seemingly opposite requirements:

**Discovery + Efficiency**

A visitor discovering SAB’A should be able to explore naturally.

A visitor who already knows what they want should be able to reach it immediately.

Neither experience should compromise the other.

---

# Navigation Hierarchy

The navigation system should establish clear levels of importance.

### Primary Navigation

Contains the most important destinations within the house.

Examples may include:

- Collections
- Creations
- The House
- Discovery

The exact naming may evolve with the final brand architecture.

### Secondary Navigation

Provides access to supporting areas.

Examples may include:

- About
- Journal
- Services
- Contact
- Customer Care

### Utility Navigation

Provides functional access.

Examples include:

- Search
- Account
- Wishlist
- Bag
- Language
- Currency

Utility functions must remain accessible without competing with the primary brand experience.

---

# Navigation as Spatial Movement

The website should behave like a coherent environment.

Moving from one area to another should feel like moving between spaces within the same house.

The visitor should experience:

**Arrival → Discovery → Deeper Exploration → Product → Purchase → Continuity**

rather than:

**Page → Page → Page → Checkout**

Transitions should preserve the sense of place.

---

# Primary Navigation

The primary navigation should remain intentionally limited.

Too many top-level destinations create:

- Cognitive overload
- Visual clutter
- Decision fatigue
- Reduced hierarchy

The visitor should not be presented with the entire architecture at once.

Complexity should exist underneath a simple surface.

---

# Navigation Labels

Labels must be:

- Clear
- Consistent
- Short
- Meaningful
- Easy to understand

Luxury does not require obscure language.

If a visitor needs to guess what a navigation label means, the label has failed.

Brand-specific terminology may be used when it creates genuine meaning and is understandable from context.

---

# Mega Navigation

Large navigation systems may be used when the number of products or collections requires them.

However, a mega menu must not become a catalogue.

It should be:

- Structured
- Spacious
- Visually calm
- Hierarchical
- Curated

It may combine:

- Categories
- Collections
- Featured creations
- Editorial entry points
- Visual discovery

The visitor should be able to scan it quickly.

---

# Discovery Through Navigation

Navigation should support exploration without forcing it.

The visitor may discover:

- A collection
- A story
- A product
- A heritage reference
- A related creation
- A new release

through contextual navigation.

The system should make discovery feel natural.

---

# Contextual Navigation

Navigation may change according to the visitor's current location.

For example:

A product page may provide pathways to:

**Product → Collection → Related Creations → The House**

An editorial story may provide:

**Story → Related Story → Collection → Product**

Contextual links should expand the world without creating confusion.

---

# Breadcrumbs

Breadcrumbs should be used where they genuinely improve orientation.

They are particularly useful in deeper structures such as:

**Collection → Category → Product**

They should remain subtle.

Breadcrumbs are a navigation aid, not a visual feature.

---

# Search

Search is a direct path for visitors with strong intent.

It should be available consistently across the website.

Search should support:

- Product names
- Collections
- Categories
- Relevant content
- Common terminology
- Useful suggestions

Search results should preserve the SAB’A environment.

A technically efficient search that looks like a generic database is not sufficient.

---

# Search States

Search must account for:

### No Search Yet

Provide a calm starting state.

### Active Search

Provide immediate feedback.

### Results Found

Present relevant results clearly.

### No Results

Explain the situation and provide useful alternatives.

For example:

- Related products
- Collections
- Popular searches
- Brand discovery

A failed search should not become a dead end.

---

# Account Navigation

The customer account is part of the wider SAB’A relationship.

The account should provide access to areas such as:

- Profile
- Orders
- Order tracking
- Wishlist
- Saved preferences
- Loyalty / points
- Rewards
- Coupons
- Available benefits
- Newsletter preferences
- Communication preferences
- Customer care
- AI assistance where appropriate

The account should feel like a private space within the house.

It should not feel like an administrative dashboard.

---

# Loyalty Navigation

Loyalty functionality should be integrated into the customer account rather than treated as a disconnected system.

The customer may be able to view:

- Current points
- Points history
- Purchases contributing to loyalty
- Rewards
- Available coupons
- Used coupons
- Progress toward a reward
- Membership status
- Exclusive benefits

The system should make the relationship visible without turning the brand into a points marketplace.

---

# Digital Loyalty Card

A digital loyalty card may eventually extend into supported digital wallet systems.

Potential future integrations may include:

- Apple Wallet
- Google Wallet
- Samsung Wallet

However, these integrations should not delay the core website launch.

The initial loyalty experience should be fully functional inside the SAB’A customer account.

Digital wallet functionality can be introduced as the infrastructure matures.

---

# Wishlist

Wishlist functionality should allow customers to preserve products they are interested in.

It should support:

- Saving products
- Removing products
- Returning to saved products
- Availability awareness where appropriate

Wishlist should encourage future discovery rather than create unnecessary pressure.

---

# Bag

The shopping bag should remain continuously accessible.

The visitor should be able to understand:

- Number of items
- Current total
- Selected products

without being forced into the checkout experience.

The bag should provide a clear transition:

**Discovery → Selection → Review → Checkout**

---

# Checkout Navigation

Checkout is intentionally different from general site navigation.

Once the visitor begins checkout, unnecessary distractions should be reduced.

The interface should prioritise:

- Order review
- Customer information
- Delivery
- Payment
- Confirmation

The visitor should still recognise SAB’A.

But the navigation should no longer compete with the transaction.

---

# Customer Care Navigation

Customer Care should be easy to find from anywhere in the website.

The customer may access support through:

- WhatsApp
- Customer care email
- AI assistance
- Relevant help content

The appropriate channel depends on the type and urgency of the request.

Navigation should make these options discoverable without overwhelming the visitor.

---

# AI Navigation

SAB’A AI may function as an additional layer of assistance.

It should help visitors with tasks such as:

- Product discovery
- Product questions
- General brand questions
- Order-related guidance
- Frequently asked questions
- Customer care routing

The AI should not replace human service where human intervention is appropriate.

It should act as a guide within the house.

---

# Social Channels

Social platforms are extensions of the SAB’A world rather than independent identities.

Relevant channels may include:

- Instagram
- TikTok
- X

Navigation to social channels should be available where contextually appropriate.

The website should not encourage visitors to leave unnecessarily.

Social links should function as extensions of discovery, community, and communication.

---

# X and Community Activity

X may serve a more immediate and interactive role.

It may be used for:

- Announcements
- Conversations
- Launch moments
- Polls
- Community interaction
- Periodic competitions
- Special campaigns
- Limited promotional events

These activities should remain consistent with the SAB’A identity.

Promotional activity should feel like an event rather than constant discount communication.

---

# Email Navigation

Email should function as an extension of the customer's relationship with SAB’A.

The website may allow customers to manage communication preferences from their account.

Communication may include:

### Transactional Email

Used for:

- Order confirmations
- Receipts
- Shipping updates
- Delivery notifications
- Account-related messages

### Marketing and Editorial Email

Used for:

- New creations
- Collections
- Stories
- Editorial content
- Special announcements
- Selected offers
- Events

### Customer Care Email

Used for:

- Questions
- Complaints
- Support
- Service requests

These functions should remain distinct while belonging to the same communication ecosystem.

---

# Global Navigation

The primary navigation should remain available across the majority of the website.

However, it may adapt in contexts where reduced navigation improves focus.

Examples:

- Checkout
- Full-screen discovery
- Certain cinematic experiences
- Focused campaign experiences

Adaptation should never make the visitor feel lost.

---

# Sticky Navigation

Sticky navigation may be used when it provides genuine value.

It should allow access to essential destinations without permanently consuming excessive screen space.

On product pages, for example, a contextual sticky purchase action may be appropriate.

The rule is:

**Persistent does not mean intrusive.**

---

# Mobile Navigation

Mobile navigation must be designed independently rather than simply compressed from desktop.

It should prioritise:

- Clear hierarchy
- Large touch targets
- Quick access
- Search
- Account
- Bag
- Primary destinations

The mobile navigation must remain recognisably SAB’A while being extremely easy to operate.

Detailed mobile requirements are defined in:

**7_Mobile Experience.md**

---

# Navigation States

Every navigation element must have clear states.

These may include:

- Default
- Hover
- Focus
- Active
- Selected
- Disabled
- Loading

The visitor should always understand the current state.

---

# Back Navigation

Visitors must be able to return naturally.

The experience should respect browser and device navigation patterns.

Do not create custom navigation behaviour that makes returning to the previous state difficult.

The visitor's sense of orientation must be preserved.

---

# Deep Linking

Every meaningful destination should be independently reachable.

Visitors may arrive directly through:

- Search engines
- Social media
- Email
- Shared links
- Campaigns
- Advertisements
- Direct navigation

A visitor arriving directly at a product or story should still understand where they are within SAB’A.

---

# Navigation and SEO

Navigation should also support discoverability through search engines.

Important pages should have:

- Logical hierarchy
- Clear naming
- Stable URLs
- Meaningful relationships
- Accessible content

Search engine optimisation must support the architecture rather than distort it.

The visitor experience remains the priority.

---

# Navigation and Personalisation

Personalised navigation may be introduced carefully.

For returning customers, relevant shortcuts may include:

- Continue shopping
- Recent products
- Orders
- Wishlist
- Rewards

Personalisation should reduce effort.

It should never hide important destinations or create a confusing interface.

---

# Navigation Consistency

Navigation patterns should remain consistent across the website.

A visitor should not have to relearn the interface on every page.

Consistency applies to:

- Placement
- Naming
- Behaviour
- Interaction
- Visual hierarchy
- Responsive behaviour

The website may evolve.

Its navigation language should remain recognisable.

---

# Navigation Quality Test

Before approving a navigation system, ask:

1. **Can a new visitor understand where to begin?**
2. **Can an intentional shopper reach a product quickly?**
3. **Can a visitor discover the SAB’A world naturally?**
4. **Can the visitor always understand where they are?**
5. **Can they return easily?**
6. **Are primary choices clearly separated from secondary choices?**
7. **Does the navigation remain calm and premium?**
8. **Does search provide a strong alternative path?**
9. **Can customers easily access their account and orders?**
10. **Can customers reach support without searching for it?**
11. **Are loyalty, rewards, and saved products easy to access?**
12. **Does the system remain coherent on mobile?**
13. **Does the navigation preserve the SAB’A character?**

---

# What Navigation Must Never Become

SAB’A navigation must never become:

- A wall of links
- A technical sitemap exposed to the visitor
- An overcrowded mega menu
- A maze
- A collection of clever but unclear labels
- A constant promotional banner
- A source of unnecessary friction

Complexity belongs behind the structure.

The surface should remain calm.

---

# Core Standard

The best navigation is often the navigation the visitor barely notices.

It should feel obvious.

It should anticipate intent.

It should support discovery.

It should preserve orientation.

It should disappear when attention belongs elsewhere.

**Navigation should never compete with the world.**

It should allow the world to unfold.

---

# Core Statement

SAB’A navigation is the invisible architecture of movement.

It guides without forcing.

It reveals without overwhelming.

It provides immediate access without sacrificing discovery.

It connects:

**The House → Collections → Creations → Account → Purchase → Ownership → Continuity**

The visitor should never feel trapped inside the website.

They should always feel that there is somewhere meaningful to go next.

**The goal is not to show the visitor everything.**

**The goal is to make the next meaningful step feel obvious.**
